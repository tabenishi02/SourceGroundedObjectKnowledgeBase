# SGOKB v2.0.0 Release Note

Updated: 2026-10-31

- Version: `2.0.0`
- Tag: **pending P-CLOSE-01 final regression and main freeze**
- Previous release: `v1.1.0`
- Compatibility: MAJOR release; default external Package/Result exchange contract changes to Raw-grounded v2

## Summary

`v2.0.0` integrates Phase P — GUI / RAW Grounding / Runtime Modernization.

The release adds the accepted PySide6 desktop GUI, makes Raw-grounded Package v2 / Result v2 the default external analysis path, and formalizes a recoverable native-Windows Qdrant runtime with shared CLI/GUI health projection.

Canonical SQLite/Object/Version semantics remain authoritative. GUI and runtime modernization do not introduce a second canonical persistence path.

## Breaking change: Package v2 becomes default

The no-option command:

```text
sgokb package build --object <OBJECT_ID>
```

now selects Package v2 / Result v2 Raw-grounding semantics.

Package v1 remains available only by explicit compatibility request:

```text
sgokb package build --object <OBJECT_ID> --package-version v1
```

Historical v1 artifacts remain valid under their original contract and are not silently reinterpreted as v2.

This default semantic change is the reason for the MAJOR version bump from `1.1.0` to `2.0.0`.

## Raw-grounded exchange

The primary external analysis path is now:

```text
selected Evidence
  -> original Normalization Run
  -> complete input Raw Artifact set
  -> exact verified Raw bytes
  -> Package v2
  -> external AI
  -> Result v2 raw_artifact_id grounding
  -> validation / review / import
  -> raw_grounding_links
  -> accepted Knowledge Version
```

Package v2 binds both manifest identity and the Raw grounding set. Result v2 references Package-member `raw_artifact_id` values and mechanically verifiable locators when present.

## Desktop GUI

Phase P adds a PySide6/Qt Widgets desktop client over the shared Application/operator layer.

Accepted GUI properties include:

- 67/67 public operation coverage under the Phase P capability matrix;
- no GUI-only canonical SQLite/Repository write path;
- Package/Result, Registry, Search, System/Maintenance and Runtime Dashboard surfaces;
- external MCP lifecycle explanation rather than a fake GUI-owned MCP daemon;
- standard desktop navigation/shortcuts and presentation-state persistence;
- runtime degradation and troubleshooting through the shared runtime-health projection.

P-CLOSE-01 does not publish/certify a standalone GUI binary artifact. Public binary redistribution remains subject to the separate project-license and PySide6/Qt artifact license gate recorded by P-GUI-02.

## Windows Qdrant runtime

The accepted Windows reference runtime is native `qdrant.exe` owned by Windows Task Scheduler:

```text
Task                  = \SGOKB\Qdrant
startup               = AtLogOn
crash recovery        = repeating TimeTrigger
recovery interval     = 60 seconds default
principal             = Interactive / Limited
multiple instances    = IgnoreNew
readiness authority   = GET /readyz -> HTTP 200
SGOKB lifecycle role  = observer/client only
```

SGOKB does not expose Qdrant start/stop/restart actions.

## Runtime health and recovery

`system status` and the GUI Runtime Dashboard share `sgokb.runtime-health/1.0` for SQLite, Embedding, Qdrant, Search generation and derived state.

P-RUNTIME-06 accepted real-host behavior for:

- Qdrant unavailable -> explicit degradation / Semantic Search blocked;
- wrong service on port 6333 -> fail closed;
- recovery to Qdrant 1.19.2 `/readyz` HTTP 200;
- persistent Qdrant collection inventory (`80 -> 80`, no diff);
- public Vector Index rebuild (`ok=true`, Qdrant green, 126 points);
- post-rebuild SQLite integrity;
- canonical Object/current-Version count stability (`5 -> 5`, `5 -> 5`).

## Compatibility

Preserved compatibility boundaries include:

- explicit Package v1 / Result v1 support;
- v1 accepted Version -> v2 update support;
- v2 -> v1 downgrade blocked by default;
- read-only MCP contract;
- canonical Object/Version/Raw/Evidence provenance model;
- rebuildable Search Representation / Embedding / Qdrant / rendering derived state.

## Migration guidance

Existing operators should review any scripts that relied on the no-option Package build producing v1.

To preserve old behavior temporarily, add:

```text
--package-version v1
```

New workflows should use the default v2 path and provide external analysis compatible with `sgokb.object-result/2.0` Raw grounding.

No canonical SQLite rewrite is required solely because the Package default changed. Existing accepted v1 Knowledge remains valid.
