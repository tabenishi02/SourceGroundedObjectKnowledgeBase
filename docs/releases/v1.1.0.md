- Version: `1.1.0`

## Summary

`v1.1.0` is the first post-`v1.0.0` minor release of Source Grounded Object Knowledge Base (SGOKB).

This release incorporates the operator-facing improvements and contract-preserving remediation completed during the full happy-path operational acceptance run. It adds explicit source-generation selection commands, fixes relation traversal from unversioned endpoints, reconciles historical derived search state across accepted Knowledge Versions, and records the completed A-T happy-path acceptance with overall **FULL SGOKB PASS**.

No canonical database schema migration is introduced by this release, and no v1.0.0 canonical data rewrite is required.

## New capability

### Explicit source generation selection in the public CLI

The public `sgokb source` CLI now exposes explicit operator-controlled selection of the effective Snapshot and Normalization Run:

```text
sgokb source select-snapshot --source <source-id> --snapshot <snapshot-id> --reason <text>
sgokb source select-run --snapshot <snapshot-id> --run <run-id> --reason <text>
```

These commands preserve the append-only selection-event contract. A later Snapshot or Run does not replace the effective generation merely because it is newer; the operator explicitly selects the reviewed generation and records a reason.

## Fixes and remediation

### Relation traversal from unversioned endpoints

Current one-hop Relation traversal can now be read from either canonical endpoint even when the queried endpoint Object does not have its own Knowledge Version.

The implementation preserves:

- canonical Relation direction;
- Relation owner Object / Version identity;
- Evidence grounding;
- pinned historical Version semantics.

No inverse Relation is synthesized and no canonical Relation is duplicated into the target Object.

### Historical derived search reconciliation

Derived Search Representation / Embedding synchronization now reconciles accepted Version history rather than only the current Version. This preserves explicit historical lexical/semantic reads after later Versions become current.

Downstream derived state is invalidated and rebuilt where historical backfill changes the active representation set, while unchanged representations remain reusable.

### Acceptance workflow corrections

The operator acceptance procedures were corrected and exercised for:

- empty Relation Type Registry startup flow;
- required derived synchronization before lexical and semantic reads;
- same-primary-class similarity fixture preparation;
- N-09 cross-class semantic retrieval remediation;
- historical derived-state reconciliation;
- final uninterrupted end-to-end workflow.

## Compatibility and migration

### Breaking Changes

None intentionally introduced relative to `v1.0.0`.

The new source-selection CLI commands are additive. Relation traversal broadens previously failing current-graph reads while preserving pinned historical semantics. Historical derived reconciliation repairs derived-state coverage without changing accepted canonical Knowledge.

### Database migration

No new canonical SQLite migration is required for the changes in this release.

Existing `v1.0.0` canonical databases remain on the same schema line. Derived Search Representation / Embedding / Vector state may be explicitly resynchronized or rebuilt using the normal maintenance commands when historical accepted Versions need backfill.

### Operational note

For follow-up captures on an existing Source, review the new Snapshot / Normalization Run and use the explicit selection commands before expecting its Evidence to become the effective generation.

## Known limitations

The v1.0.0 documented limitations remain unless separately superseded:

- MCP remains read-only for canonical operations.
- Semantic / Hybrid / Similarity operations require the configured local embedding and vector runtime.
- local provider failure does not silently fall back to cloud.
- External semantic integration remains a Human-in-the-loop boundary.
- Production-scale performance claims remain limited to the accepted benchmark/reference-workstation scope.

The happy-path acceptance also recorded a non-blocking Evidence Package selection weakness during P-01 fixture remediation; that observation remains documented separately and does not invalidate the FULL SGOKB PASS verdict.
