# SGOKB v1.0.0 Release Note

Updated: 2026-10-25

- Version: `1.0.0`
- Tag: `v1.0.0`
- Release line: first formal Source Grounded Object Knowledge Base release
- Replaces: untagged historical Prototype 0.2 line

## Summary

`v1.0.0` is the first formal release boundary for Source Grounded Object Knowledge Base (SGOKB).

This release does **not** continue the old Prototype 0.2 architecture. It establishes the redesigned Object-centered Knowledge Base as the current supported baseline after Phase A–N implementation and acceptance, followed by Phase O documentation and Git cleanup.

Prototype 0.2 remains available only as archived historical material under `docs/archive/prototype-0.2/` and through Git history.

## Current architecture

The current canonical path is:

```text
Source / Snapshot / Raw Artifact
        -> Evidence
        -> Object Evidence Retrieval / Selection
        -> Evidence Package
        -> explicit external AI step
        -> Structured Object Result
        -> validate / review
        -> explicit import
        -> accepted Object Knowledge Version
        -> lexical / semantic / hybrid / similarity retrieval
        -> CLI / MCP read access
```

Canonical Knowledge is the accepted structured Object Knowledge Version with provenance back to Evidence and Source. Markdown rendering, embeddings, Qdrant indexes and Evidence Packages are derived or reproducible artifacts rather than canonical truth.

## Breaking Changes from Prototype 0.2

### 1. Fragment / Final Document model removed from current canonical workflow

Prototype 0.2 centered on:

```text
Raw -> Fragment -> Final Document
```

v1.0.0 uses:

```text
Source / Evidence -> Object Knowledge Version
```

Fragment and Final Document are no longer canonical Knowledge concepts in the active system.

### 2. Prototype database is not upgraded in place

Prototype DBs are not supported as an in-place migration source for v1.0.0.

- legacy Fragment / Final Document tables are retired from the active schema
- Prototype migrations 001 / 002 are not part of the current clean bootstrap
- legacy Prototype DB detection fails closed
- no automatic conversion from Prototype DB rows to accepted Object Knowledge is provided

Preserve useful Raw Capture material separately and import it through the current Source / Evidence workflow.

### 3. Public CLI changed to Object-centered `sgokb`

The supported public CLI is the `sgokb` namespace.

Legacy Prototype generation commands, compatibility wrappers and Fragment / Final Document commands are not part of the v1.0.0 public contract.

Relation writes must go through Evidence-grounded Object Result import rather than direct canonical mutation.

### 4. Search representation changed

The current semantic representation contract is hierarchical multi-vector R2:

```text
object_overview
facet
statement
```

Evidence Search uses its own evidence representation family.

Old Prototype Fragment embeddings and old vector indexes are not compatible derived indexes for v1.0.0. Rebuild derived indexes from current canonical Knowledge.

### 5. External AI workflow changed

The old standard assumption of routing all Evidence through an automatic generation pipeline is retired.

v1.0.0 uses an explicit external boundary:

```text
Evidence Package
  -> explicit export
  -> ChatGPT / external AI
  -> result.json
  -> validate / review
  -> explicit import
```

ChatGPT API is not required for canonical Knowledge storage.

### 6. MCP is read-only in v1.0.0

The supported MCP surface is read-only.

Active capabilities:

```text
search_objects
find_similar_objects
get_object
get_objects
get_object_relations
get_object_evidence
search_evidence
build_context
```

Canonical writes are not exposed as MCP tools in this release.

### 7. SGOKB and UPDS responsibilities are separated

SGOKB owns World / Object Knowledge.

User preference, value and personal-inference logic belongs to UserPreferenceDiscoverySystem (UPDS) and is not stored as SGOKB Object Knowledge.

## Migration guidance

For users or local environments containing Prototype 0.2 assets:

1. Do not attempt an in-place upgrade of the old Prototype database.
2. Preserve Raw Capture files that remain useful.
3. Create a fresh v1.0.0 canonical database using the current migration chain.
4. Re-import useful Source material through the current Source / Evidence workflow.
5. Rebuild Search Representation / embedding / Qdrant derived indexes from current canonical Knowledge.
6. Update automation and scripts to the `sgokb` CLI contract.
7. Update MCP clients to the read-only v1.0.0 tool contract.
8. Review the current 1 Object workflow before importing external AI Results.

## Acceptance basis

The v1.0.0 release boundary is based on the accepted Phase N closure state:

```text
N-01 = Complete
N-02 = Complete
N-03 = Complete
N-04 = Complete / PASS
N-05 = Complete / PASS
N-06 = Complete / PASS
N-07 = Complete / PASS
N07-R01 = Complete / PASS
Phase N closure audit = Complete / PASS
```

Formal Phase N closure evidence is preserved in:

- `docs/evaluation/PHASE_N_CLOSURE_AUDIT.md`
- `docs/planning/phases/N/PHASE_N_CLOSURE_AUDIT.md`
- `benchmark/results/phase-n-closure-audit.json`

The original N-07 historical `47 PASS / 3 FAIL` result remains preserved and is not rewritten; later N07-R01 remediation and Phase N closure evidence establish the accepted final state.

## Known limitations

- The initial MCP surface is read-only.
- Semantic / Hybrid / Similarity operations require the configured local embedding and vector runtime.
- A failed local provider does not silently fall back to cloud.
- Production-scale performance claims are limited to the accepted benchmark/reference-workstation scope.
- Retention targets are documented, but an independent durable scheduler is outside the core release contract.
- External semantic integration remains a Human-in-the-loop boundary rather than a fully automatic canonical write path.

## Prototype boundary

No historical Prototype tag is created retroactively.

```text
Historical Prototype 0.2
  -> archived docs + Git history

v1.0.0
  -> first formal current SGOKB release boundary
```

This avoids implying that an old Prototype commit had been formally released when no tag or GitHub Release existed at the time.
