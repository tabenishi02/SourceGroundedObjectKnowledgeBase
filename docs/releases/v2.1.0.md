## Summary

`v2.1.0` packages the accepted post-Phase-P GUI startup and runtime-health work completed after the immutable `v2.0.0` release.

The release adds a consoleless Windows source-checkout launcher, an immediate startup splash, and a corrected Search-generation health projection for the already-supported no-explicit-generation legacy retrieval route. It also incorporates completed GUI normal-path integration acceptance and the cross-document consistency audit.

No canonical SQLite/Object/Version schema, public CLI command contract, MCP public tool contract, Package v2 contract, or Result v2 contract is broken by this release.

## Windows consoleless GUI launcher

A Windows source checkout with the repository virtual environment can launch SGOKB through:

```text
scripts\launch-sgokb-gui.vbs
```

The launcher uses:

```text
.venv\Scripts\pythonw.exe -m sgokb.gui.main
```

and does not leave PowerShell, CMD, or a persistent script window open while the GUI is running. The existing packaged `sgokb-gui` entrypoint remains supported.

## Startup splash

GUI startup now exposes an immediate `QSplashScreen` before the heavier SGOKB runtime/view imports and native semantic dependency initialization.

The accepted ordering is:

```text
QApplication
-> show / flush QSplashScreen
-> import SGOKB runtime/view modules
-> preload local semantic native dependencies on the Qt main thread
-> create BackendCoordinator / backend QThread
-> show MainWindow
-> finish splash
```

This is a presentation/startup improvement only. It does not introduce a second runtime or canonical write path, and it preserves the accepted native-preload-before-QThread safety boundary.

## Search-generation runtime health correction

When current accepted Knowledge exists and there is no explicit Search-generation pointer, generation-aware retrieval can intentionally use the supported legacy compatibility route.

That state is now reported as:

```text
Search generation = HEALTHY
active=none (legacy routing)
routing_mode=legacy
issue=none
```

Previously this valid route was projected as `DEGRADED / generation_not_active`, producing a false operator warning.

The correction is classification-only:

- opening or refreshing Runtime Dashboard does not build or activate a generation;
- explicit missing/stale/not-ready generation state remains degraded;
- Qdrant readiness/failure behavior is unchanged;
- Search execution semantics are unchanged;
- `sgokb.runtime-health/1.0` remains the schema version.

## Compatibility and migration

No data migration is required from `v2.0.0` to `v2.1.0`.

Existing Workspaces, accepted Knowledge Versions, Package v1 compatibility, Package v2/Result v2 Raw grounding, read-only MCP behavior, Qdrant external lifecycle ownership and derived-state rebuild semantics remain supported.
