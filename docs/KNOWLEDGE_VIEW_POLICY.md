# 概要Viewの選択と網羅的Finalの利用方針

更新日：2026-10-07。

## 今回の変更

従来のViewは、Claim IDの順とfacet・情報種別の巡回を基準に選んでいた。このため、人物の定義よりスキル・楽曲・二次創作が先に入り、作品の概要より個別イベントが先に入る問題があった。short/standard/detailedの予算差だけでは、本質的な情報から補足へ広げる構成にならなかった。

選択を `entity-overview-priority-v2` に変更する。入力Fragment、Claimの本文・根拠・metadata、網羅的Finalは変更しない。既存の予算と省略manifestを維持する。

1. 対象自身の定義・概要を最優先する。
2. 所属・性格、作品のジャンル・開発元など、対象を説明する主要項目を優先する。
3. 年齢・特徴・趣味などのプロフィールへ広げる。
4. 関連人物の属性、カード・スキル・楽曲・イベント・二次創作などは後に回す。弱い推論・評判・宣伝は定義と同格にしない。
5. 同義のfacetを選択上のtopicへまとめ、同じ所属や定義の反復より異なる基本項目を先に選ぶ。これはClaim自体の意味的な統合ではない。未選択の別Claimも保持する。
6. queryがある場合は語の一致を優先し、質問に必要な個別情報を概要より先に選べるようにする。

## 各Viewの役割

| View | 役割 | 優先する内容 |
|---|---|---|
| short | 初めて対象を知るための入口 | 何であるか、どこに属するか、どのような特徴・性格・ジャンルか |
| standard | 対象の基本情報を把握する | shortの基本項目を中心に主要属性・特徴を広げる |
| detailed | 補足まで読む | 基本情報に加え、関連する主張や個別事項を広げる |
| context | 特定の質問に答える材料 | queryに関連する主張と出典 |

mode名と用途を本文にも表示する。本文は出典由来のClaimをそのまま選び、生成LLMで新しい総括文を作らない。同じ重要な情報を複数modeに残すことは意図した動作であり、modeごとに無関係な内容へ切り替えるものではない。

選択は共通の優先順と予算による。各modeが必ず同じClaimの厳密な包含関係になることや、情報量が必ず一定倍率になることは保証しない。長いClaimが予算に入らない場合も省略manifestに残る。

## 残る制約

重要度はfacetとsubjectによる決定的なルールで判定する。一般的な意味理解を実現したものではなく、未知のfacet・別表記・誤ったsubjectには対応限界がある。出典数は支持の数として参照するが、独立した裏付けや真実性の点数ではない。相反する主張の真偽を決めたり、古い情報を自動的に最新へ置換したりしない。

現行counterは保守的なUTF-8バイト数。本文の出典とstructured metadataにも予算を使うため、表示Claim数は限定される。短いViewが必要なすべての情報を保持するかは、実際の質問・利用目的と人間の評価で確認する。

## 網羅的Finalの位置付け

網羅的Finalは、全主張と出典の確認・監査・再生成の基準資料として保持する。通常の入口はshort/standard、掘り下げる場合はdetailedまたは検索を使う。完全Finalをそのまま毎回読むことや、丸ごとLLMのcontextへ送ることを既定の利用方法にしない。

| 利用場面 | 利用する資料 | Finalの役割 |
|---|---|---|
| 対象の把握 | short/standard | 省略された主張を確認できる完全資料 |
| 詳細な調査 | detailed・検索結果・元Evidence | 全体の分類・時系列・相違点を確認 |
| AIへの質問 | query付きcontext、関連Fragment/Evidence | 質問用資料を作る際の網羅的な保持基盤。全量送信はしない |
| 誤り・帰属の確認 | Claim → Fragment → Evidence | 出典と主張の対応を監査する |
| 将来の表示変更 | 保存済みの構造化資料 | 再抽出せず別のViewへ組み替える |

これらの経路のうち、検索から元Evidenceへの参照と予算制限Viewは既存機能を利用できる。閲覧UIや自動的な検索連携画面の新規実装まで完了したという意味ではない。

完全Finalの脚注は変更後のCharacterで約73%、Workで約63%の文字数を占めている。次の表示改善候補は、共有出典へ短い参照番号を振り、詳細なSnapshot・Evidence・位置情報を別の監査表示へ分離すること。時系列での再掲も本文の長さに影響するため、脚注だけを減らしても十分な要約にはならない。これは検討事項であり、今回の概要選択修正ではFinalの生成・保存形式を変更しない。
