# 代表8Capture 再抽出比較の評価

評価日：2026-10-07。評価者：Codex。対象：efficiency-capture-comparison-v2。

## 総合判断

**条件付き採用。効率化の実装は継続利用する価値がある。ただし、抽出品質を維持した全面的な成功や、無人運用の安定性確立とは判定しない。**

同じStrata構成で全8Captureの累積処理時間が短縮し、入力・出力tokenと呼出回数も減少した。Rawと元DBを保持して全16ケースを完了できたことは明確な成果である。一方、意味品質の正解データがなく、限定的な目視でも内容の変化を確認した。人間が抽出内容を確認する非同期バッチ運用には採用を推奨する。品質確認なしでFinal Documentへ反映する運用の承認は保留する。

## 観点別の判定

| 観点 | 私の判定 | 根拠 |
|---|---|---|
| 処理コスト削減 | 成果あり | 全8Captureで時間短縮。合計32.2%短縮、入力20.7%・出力18.2%削減 |
| 実行・データ整合性 | 合格 | 前後16ケース完了、Raw不変、全DB integrity正常・外部キーエラー0、元DB不変 |
| 抽出品質の維持 | 保留 | 件数・引用検証だけではRecall/Precisionを証明できず、目視でも内容差を確認 |

| 無人での連続運転 | 未確立 | GPUタイムアウト・形式違反による停止と手動介入が発生 |
| 運用上の応答時間 | バッチ用途なら許容 | 変更後でも8Captureに約4時間42分。即時応答の前処理としては重い |

## 抽出内容についての評価

総件数がほぼ同じでも、Captureごとの増減が相殺されている。fragment-01は349→283、fragment-02は136→174であり、件数が同じだから取りこぼしがないとは判断できない。

内容と主要metadataを含む完全一致は214件で、変更前5,337件に対して約4.0%。facetの名称や表現、時期・帰属などの差も不一致に含まれるため、これを96%の情報喪失と読むのは誤りである。しかし、単なる保存形式の変更だけではなく、抽出結果が変化していることは分かる。

fragment-04の変更前3件・変更後2件を全件確認した。2件には対応する主張があり、完全一致0件でも内容がすべて失われたわけではない。一方で次の懸念を確認した。

- 変更前の誕生日を祝う投稿についての弱い推論は、変更後に対応するFragmentがない。入力の引用は祝いの文言で、対象人物への帰属には推論が含まれる。省略は過剰推論の抑制にも、High Recall上の取りこぼしにもなり得るため、正解ラベルなしでは優劣を断定しない。
- 別の主張では、変更前の本文にあった「主張されている」という帰属表現が、変更後では断定文へ変わった。metadataにはpublic_perceptionとanonymous_userが保持されているため保存上の区別は残るが、本文だけを表示する用途では意見を事実に見せる懸念がある。

この目視確認は限定的で、全5,356 Fragmentの意味妥当性を確認したものではない。Schema適合・引用の存在は、引用が主張を十分支持すること、正しい時期・対象・強度で解釈したこと、1件1主張への分割を保証しない。

## 試験条件による限界

- モデルはQwen3.8-Flash-Next IQ3_S、Strata engine 0.1.39、context 65536、KV int8、cvec project:4-44、spec 6、mtp_max 4、lookup 3。出力上限8192 token。
- 変更前は94f7e9c、変更後は4d14b48を基準とし、変更後fragment-08の再試行に7551812の診断修正を適用。変更後1〜7の成功結果は保持した。同一修正commitで全8件を再測定した試験ではない。
- 変更前の成功済み1〜7は既存測定を再利用。モデル・runtime・入力等は照合したが、全ケースを同じ連続セッションで測定したものではなく、cacheやサーバー再ロードの影響を除去していない。
- GPUタイムアウト後の回復と失敗attemptも累積値に含む。失敗166→14を、実装変更だけによる安定性向上率とは扱わない。
- 8Capture各1系列の運用評価で、独立した反復測定や誤差幅はない。純粋な速度効果の厳密な推定には、障害のない同一条件での反復が必要。
- 今回測定したのは再抽出工程。検索・Embedding・Final Documentの品質や処理時間を今回の結果で合格扱いしない。

## 次に優先する確認

1. 品質確認を優先する。減少したfragment-01/03/04/06、増加したfragment-02/08について、実Evidenceから必要な主張・帰属・時期を人間がラベル付けし、取りこぼし・根拠不十分な主張・複数主張の混在を比較する。変更前も正解として扱わない。
2. 意見の帰属を失わない表示を確認する。本文だけの表示とFinal Documentでも、public_perception等の区別が伝わるか評価する。
3. 品質を確認してから速度の反復試験を行う。長いCaptureと短いCaptureでcache条件と中断を分離し、中央値・ばらつき・失敗数を記録する。
4. 当面は完了通知・失敗記録・明示的な再開を伴うバッチ運用に限定する。自動再試行の拡張が必要な場合も回数を制限し、検証違反を合格へ書き換えない。

これらは次段階への提案であり、本評価作成で実施した追加試験ではない。
